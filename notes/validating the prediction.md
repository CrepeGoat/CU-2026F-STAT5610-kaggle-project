# using unconditional response rates

one of our core assumptions about our dataset is that *the training and test data are drawn from the same distribution*. this distribution has some unconditional positive response rate $\Pr (Y = 1)$, which should agree with the distribution of the conditional probability $P = \Pr \left(Y = 1 \mid X\right)$ for some distribution of conditioned variables $X$:

$$
\begin{align}
E [P]
	&= E _{X} \left[\Pr \left(Y = 1 \mid X\right)\right] \\
	&= \Pr (Y = 1) \\
\end{align}
$$

-> given this, our modeled probabilities should yield the same unconditional probabilities as the training data:

$$
\frac{1}{n} \sum _{j = 1}^{n}\hat{p} _{j}
	\approx \frac{1}{m} \sum _{i = 1}^{m} \mathbb{1} \lbrace Y _{i} = 1\rbrace
$$

# simulating F-scores

unfortunately, since the F-score is not linear on its requisite parameters (i.e., TP & TN rates), there is no easy way to analytically compute its expectation, variance or confidence intervals. in lieu of this, we can calculate approximate values for these quantities using MC simulations. 

specifically, we can consider each test response as a bernoulli RV with probability equal to our model estimates $\hat{p} _{i}$. simulating the test response involves drawing a random bernoulli result for each test point, and based on our established decision threshold, we then assign each test point response as either TP, TN or other. collecting these results over the whole test sample gives us a TP & TN rate, from which we can calculate an F-score. repeating this process then gives us a simulated sample of F-scores, from which we can derive an approximate distribution using methods like KDE, or calculate different metrics like the mean, variance, median, CI bands, etc.

## reduction for reported F-scores

there is a small caveat to using this method for the purposes of comparing against the reported F-score. as stated on the Kaggle competition page (TODO where again?), the public reported score is based on ~30% of the test data. this means the public score is actually subjected to more variance than the full score, since it's based on fewer data points.

to account for this, we can change the simulation to only use 30% of the data when generating F-scores. however, since we don't know what subset of the data is used for public scores, we select this subset randomly on each F-score simulation. then we proceed as described above on this subset, and randomly choose a new subset for each F-score simulation.
